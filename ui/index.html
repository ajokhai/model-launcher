Model Launcher
–

Your models

Everything lives in ~/Models, one folder per model. Launch one and it loads; on a Mac with room, several stay loaded at once.

Discover

Open models picked to run well on a Mac, downloaded straight from huggingface.co. Each card links its source and license; the badge says how it fits your memory budget. Want one that isn't here? Use + Add a model in Library.

Studio

Try voice, image and video models right here. The same features are in the API and MCP.

Speak

Text to speech with a local voice model.

Transcribe

Speech to text. Drop or choose an audio file (wav, mp3, m4a…).

Image

Describe a picture. Turbo models take a few seconds.

Video

Describe a short clip. Video is the heaviest thing a Mac can run locally: a 2-second clip takes minutes.

Connect

Use your local models from other apps. Nothing leaves this Mac.

    Help
    Quick answers. The full docs are on GitHub.
    
      
    
        
    Getting started
          
    1. Open Discover and download a model marked Runs great.
      2. 
          
    2. In Library, press Chat. The model loads and a chat window opens.
      3. 
          
    3. For voice and images, get a Whisper, OuteTTS or SD Turbo model and try it in Studio.
    
          
    Engines are installed for you the first time they're needed (Settings › Engines).
    
        
    Can I use a model that isn't in Discover?
          
    Yes. Press + Add a model in Library. You can paste a Hugging Face link and it downloads, choose files already on your Mac and they're moved into ~/Models, or make a folder by hand. The window walks you through each, and the docs have a full example. Any GGUF chat model that llama.cpp supports works (Mistral, Phi, DeepSeek, Llama, Qwen and more), as do Whisper models and Stable Diffusion GGUF or safetensors files.
    
        
    Where are my models?
          
    All in ~/Models: Chat, Voice and Image, with one folder per model. To add a model from elsewhere, put its files in a new folder there (for example ~/Models/Chat/My Model/). A .gguf plus an optional mmproj-*.gguf makes a chat model; a ggml-*.bin in Voice is a Whisper model. To remove one, use the trash button or delete its folder.
    
        
    How does memory management work?
          
    You set a memory budget. Before loading, Model Launcher estimates what a model needs and refuses it if that's over the budget or more than is free. While it runs, a watchdog measures real memory every two seconds and stops anything that grows past the budget. Several chat models can be loaded at once (Settings › Chat models at once) as long as together they fit the budget; when a new one doesn't fit, the least recently used one is unloaded. Voice and image jobs run one at a time and unload chat models the same way if they need room. Idle chat models unload on their own.
    
        
    What do the fit badges mean?
          
    Runs great uses under 75% of your budget. Fits is within budget. Over budget means your Mac could run it if you raise the budget. Too big needs more memory than this Mac has.
    
        
    My Mac feels slow while a model runs
          
    In Settings, lower CPU threads, keep Low priority on, lower Context size, or pick a smaller model. Quitting Model Launcher always frees all model memory.
    
        
    Using models from other apps
          
    See Connect. Any OpenAI-compatible app can use http://127.0.0.1:11500/v1. MCP apps like Claude and Cursor can be connected with one click. Only this Mac can reach the API, and web pages can't.
    
        
    Where do the models come from?
          
    Every model in Discover is a direct download from Hugging Face, made by the lab named on its card. Each card's Source line links the original model, the repo its files come from (often an official GGUF conversion, or a community one such as bartowski's), and its license. Licenses differ: Apache 2.0 and MIT models are free for any use, while Gemma, Llama 3.2, Stability AI and OuteTTS (non-commercial) have their own terms. Read them before commercial use.
    
          
    Models run on open-source engines: llama.cpp and whisper.cpp by ggml.ai, and stable-diffusion.cpp by leejet, all MIT licensed. Model Launcher is MIT licensed too.
    
        
    Unimodal or multimodal?
          
    Each card shows what a model takes in and gives back. Unimodal models work in one kind of data (text in, text out). Multimodal ones cross kinds: text and images in (vision chat models), audio to text (Whisper), text to audio (OuteTTS), text to an image (Stable Diffusion) or text to video (Wan).
    
        
    A model won't load
          
    Check Settings › Activity for the reason. Logs are in ~/Library/Application Support/Model Launcher/logs. Make sure the engine shows as installed in Settings › Engines.
    
      
    
    
    
  
    

  
    
    
    
      
    Add a model from anywhere
    
      
    Bring any open model that runs on llama.cpp, whisper.cpp or stable-diffusion.cpp. It goes into ~/Models with the rest.
    
      
    

      
    
        
      
          
    1. Find the model on Hugging Face (search for its name plus GGUF). Official labs often publish their own GGUF, and trusted community converters include bartowski, unsloth and ggml-org.
      2. 
          
    2. Open Files and versions and pick one file. Q4_K_M is the best balance of size and quality; the file should be smaller than your memory budget.
      3. 
          
    3. Copy the file's link (the page link or the download link both work) and paste it below. For a vision model, also paste its mmproj file.
      4. 
        
    
        
      
    
      
    
        
      
          
    1. Have the model files on this Mac: a .gguf for chat (plus an mmproj-*.gguf for vision), a ggml-*.bin for Whisper, or a .gguf / .safetensors for images. Models from LM Studio, Ollama exports or a download folder all work.
      2. 
          
    2. Choose them below. They're moved into ~/Models, not copied, so they don't take up space twice.
      3. 
        
    
        
    No files chosen
    
      
    
      
    
        
      
          
    1. Open ~/Models and go into Chat, Voice or Image.
      2. 
          
    2. Make a new folder named after the model, for example Chat/Mistral 7B.
      3. 
          
    3. Put the model's files in it. A chat folder needs one .gguf, plus an optional mmproj-*.gguf for vision. A voice folder needs a Whisper ggml-*.bin, or a TTS .gguf with its WavTokenizer*.gguf. An image folder needs one .gguf or .safetensors.
      4. 
          
    4. Come back here. It shows up in Library within a couple of seconds, and the folder name is its id in the API and MCP.
      5. 
        
    
      
    

      
    
        
        
        
      
    
      
    Check the model's license on its page before using it commercially. Only add files from sources you trust: model files are data, but a bad conversion can crash its engine.
